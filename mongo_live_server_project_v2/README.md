# Enterprise Web Frameworks – MongoDB and Express project

This project brings together the backend, REST API, CRUD, frontend integration, bcrypt and Mongoose relationship work in the supplied lectures and practicals.

## Project layout

- `backend/src/index.js` loads `.env`, connects to MongoDB and starts Express.
- `backend/src/app.js` configures middleware, mounts API routes and serves the separate frontend folder.
- `config/database.js` connects Mongoose to MongoDB.
- `models/` contains the User and Post schemas.
- `controllers/` contains request handling and database operations.
- `routes/` maps HTTP methods and URLs to controllers.
- `frontend/` contains browser HTML, JavaScript and CSS.

## Setup in VS Code

1. Install Node.js LTS and MongoDB Community Server, and make sure the MongoDB service is running. Alternatively, use your own MongoDB Atlas URI.
2. Open this project folder in VS Code.
3. In the `backend` folder, copy `.env.example` to a new file named `.env`.
4. Check `MONGODB_URI` in `.env`. The supplied local example is `mongodb://127.0.0.1:27017/test`.
5. Open a terminal in `backend` and run:

   ```bash
   npm install
   npm run dev
   ```

6. Visit `http://localhost:4000/`.

Do not use VS Code Live Server for this arrangement. Express serves the frontend on port 4000 so the browser's relative `/api/v1/...` fetch requests go to the same server.

## API endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/v1/posts/getPosts` | Retrieve posts (with populated author where available) |
| POST | `/api/v1/posts/create` | Create a post |
| PATCH | `/api/v1/posts/update/:id` | Partially update a post |
| DELETE | `/api/v1/posts/delete/:id` | Delete a post |
| POST | `/api/v1/users/register` | Register a user (password hashed with bcrypt) |
| POST | `/api/v1/users/login` | Check login credentials |
| POST | `/api/v1/users/logout` | Demonstration logout endpoint |
| GET | `/api/v1/users/getUsers` | Retrieve users without password hashes |

## Important learning/security notes

- `createdBy` is an optional ObjectId reference to the `User` model. It is optional to support older posts created before the relationship practical.
- `populate("createdBy", "username email")` returns selected user details for linked posts.
- The user ID selected in the form is a teaching demonstration only. There is no JWT authentication or ownership authorisation in this classroom project; do not deploy it as a production application.
- `.env` contains credentials and is excluded by `.gitignore`. Never commit it or share a real Atlas URI/password.
- `package-lock.json` and `node_modules` are generated by `npm install`; they are not source files to write manually.

## Testing

- Open `/api/v1/posts/getPosts` and `/api/v1/users/getUsers` in a browser to test GET endpoints.
- Use Postman for POST, PATCH and DELETE endpoints if required by the practicals.
- Register a user first, then create a post and optionally select that user as its author.
- Test Edit and Delete from the webpage.
